# 🦎 게코 하우스 서바이벌 (Gecko House Survival)

> 음식을 먹고 똥 게이지를 채운 뒤, 로봇청소기를 피해
> **거실 바닥의 44%를 '똥 땅'으로 만드는** 쿼터뷰 3D 생존·영역 확장 게임.

플레이어는 점(點)으로 칠하고, 로봇청소기는 선(線)으로 지운다.
화면의 초록색이 실시간으로 늘고 줄어드는 것 자체가 게임의 피드백이다.

---

## 실행

```bash
npm install
npm run dev        # http://localhost:5173
```

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 타입 검사(`tsc --noEmit`) + 프로덕션 빌드 |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm test` | 단위 테스트 (Vitest) |
| `npm run test:e2e` | 스모크 테스트 (Playwright) — 개발 서버 23개 + **프로덕션 빌드 3개** |
| `npm run balance` | **밸런스 검증** — 불합격이면 exit 1 |
| `node tools/cycle-probe.ts` | 봇 플레이로 실제 사이클·도달 시간 실측 |

E2E 를 처음 돌리기 전에 브라우저를 한 번 받아야 한다: `npx playwright install chromium`

`test:e2e` 는 서버를 두 개 띄운다 — 개발 서버(5173)와 **실제 빌드 산출물**(4173).
후자는 `npm run build` 를 포함하므로 첫 실행이 조금 오래 걸린다.
프로덕션 쪽만 돌리려면 `npx playwright test --project=production`.

같은 판을 다시 보고 싶으면 주소에 시드를 붙인다: `http://localhost:5173/?seed=1337`.
재시작해도 그 시드에서 파생되므로 세션 전체가 재현된다. (§0-5)

## 조작

| 키 | 동작 |
|---|---|
| `WASD` / 방향키 | 8방향 이동 |
| `Shift` | 짧은 달리기 (1.5초 지속 / 3초 쿨다운) |
| `E` 또는 `Z` | 상황별 상호작용 — 먹기 / 담요에 숨기 / 가구 오르내리기 / 화장실 / 변기 |
| `Space` | 똥 싸기 |
| `Esc` | 일시정지 |
| `M` | 음소거 |
| `R` | 클리어·게임오버 후 재시작 |
| `` ` `` | 디버그 패널 (**개발 빌드 전용**) |

실행하면 로딩을 거쳐 타이틀 화면에서 멈춘다. 아무 키나 누르면 시작하고,
그 첫 입력에서 오디오가 언락된다. 타이틀에서 튜토리얼과 효과음을 끌 수 있고,
설정은 `localStorage` 에 남는다.

## 게임 규칙

1. **슈퍼푸드 3개**를 먹으면 똥 게이지가 가득 찬다.
2. 게이지가 찬 상태에서 `Space` — **1초 동안 움직일 수 없고 무적도 아니다.**
3. 배변 지점 반경이 초록색 '똥 땅'이 된다. **이미 확보한 곳에 겹쳐 싸면 손해다.**
4. 로봇청소기가 돌아다니며 똥 땅을 지운다. 부딪히면 하트가 1개 준다.
5. 거실 유효 바닥의 **44%** 를 확보하면 승리. 하트 3개를 모두 잃으면 패배.

**핵심 트레이드오프**

- 게이지가 가득 찬 상태에서 음식을 먹으면 초과분이 버려진다 → "먼저 쌀지, 더 먹을지"
- 성장하면 배변 반경이 커지지만 **히트박스도 커진다** → 강해질수록 눈에 띈다
- 넓은 미개척지 한복판이 가장 많이 벌지만 가장 위험하다

**피난처는 공짜가 아니다**

| | 얻는 것 | 잃는 것 |
|---|---|---|
| 담요 밑 (`E`) | 청소기·인간 판정 제외 | 6초 뒤 경고, 4초 더 있으면 강아지에게 하트 -1 |
| 가구 위 (`E`) | 판정 제외 + 시야 확보 | **배변 불가** — 그동안 영역은 계속 깎인다 |
| 화장실 (`E`) | 변기 한 방에 34칸 + 청소기 8초 감속 | 왕복 20여 초, **그동안에도 거실은 계속 청소된다** |

셋 다 배고픔은 계속 줄어든다. 안전한 곳에서 버티는 전략은 성립하지 않는다.

## 기술 스택

TypeScript(`strict`) · Vite · Three.js · Vitest · Playwright.
React 를 쓰지 않는다. **외부 물리 엔진도 쓰지 않는다** — 필요한 건 원-AABB 와
원-원 판정뿐이라 `world/CollisionMap.ts` 에 직접 구현했다.

### 설계 원칙

| 원칙 | 구현 |
|---|---|
| **가구 배치는 한 곳에만** | `world/furnitureLayout.ts` 하나에서 ① 렌더 메시 ② 충돌 AABB ③ 격자 `BLOCKED` 셀이 모두 파생된다 |
| **게임 로직은 Three.js 를 모른다** | `core/`·`systems/` 는 순수 TypeScript. 덕분에 **렌더러 없이 실제 시스템으로 밸런스를 실측**할 수 있다 (`tools/cycle-probe.ts`) |
| **결정적 시뮬레이션** | 고정 1/60초 타임스텝 + 시드 기반 PRNG. 같은 시드는 같은 판을 만든다 |
| **밸런스 계산식은 한 곳에만** | `core/BalanceModel.ts` 가 `GameConfig` 를 직접 읽는다. 상수를 바꾸면 검증 결과가 자동으로 따라온다 |

`tests/architecture.test.ts` 가 이 규칙들을 코드로 강제한다 —
순수 계층의 Three.js import, `Math.random()` 직접 호출, `CONFIG` 중복 정의를 막는다.

## S9 — 테스트 정비·성능

E2E 가 개발 PC 에서 간헐적으로 깨지던 문제를 **임계값을 낮추지 않고** 해결했다.
원인은 네 가지였고, 둘은 제품 코드의 결함이었다.

| 원인 | 실제로 무슨 일이 났나 | 조치 |
|---|---|---|
| **시드가 `Date.now()`** | §0-5 는 "같은 시드면 같은 판"을 요구하는데 밖에서 시드를 줄 방법이 없었다. 실행마다 음식 배치가 달라져, 가구 옆에서 `E` 를 누르는 테스트가 하필 그 자리에 음식이 스폰된 실행에서만 깨졌다 — 재현이 안 되니 원인도 못 찾는다 | `?seed=1337` 지원. 재시작도 그 시드에서 파생돼 세션 전체가 재현된다 |
| **`droppedTime` 이 리셋되지 않음** | 로딩·타이틀 구간의 히치(셰이더 컴파일·첫 렌더)가 계속 누적돼, 부팅에서 한 번 튄 게 그대로 "플레이 중 성능 문제"로 보고됐다. §19 패널의 값도 재시작하면 의미가 없었다 | `GameLoop.resetStats()` 를 판 시작·재시작에서 호출 |
| **벽시계로 게임 시간을 잼** | 배변 애니메이션 1초는 게임 시간인데 테스트는 벽시계 3초를 기다렸다. 프레임이 밀리면 게임 시간 1초가 벽시계 3초를 넘는다 | `expectWithinGameTime` — 예산은 게임 시간, 벽시계는 안전망 |
| **`E` 의 대상을 가정함** | 음식은 사정거리 안이면 등반·화장실보다 **항상 우선**이다. 테스트는 그걸 모른 채 눌렀다 | `debug.interaction()` 으로 무엇이 걸렸는지 확인 후 누른다 (`pressInteract`) |

그 밖에:

- **소크 테스트가 실은 게임을 돌리지 않고 있었다.** 무작위 보행은 시작점 주변만
  맴돌아 음식(6.5 units 밖 스폰)에 한 번도 닿지 못했다. 이전에는 `Math.random()`
  의 운으로 가끔 통과했을 뿐이다. 가장 가까운 음식을 향해 걷도록 고치니
  **플레이 중 지오메트리가 는다**는 별개의 신호가 드러났다.
- 그 신호는 누수가 아니었다. `renderer.info.memory` 는 메시가 **처음 그려질 때**
  올라가는 것까지 세므로, Lvl 2 에서 인간이 등장하면 아무것도 새로 만들지 않았는데
  57 → 59 → 62 로 오른다. 씬 그래프가 참조하는 리소스 수를 직접 세는
  `debug.sceneStats()` 를 추가해 착시를 없앴다. (R5)
- **프로덕션 빌드 E2E 를 추가했다.** S8 은 "디버그 UI 가 번들에 없다"를 문자열
  grep 으로만 확인했는데, 이름이 사라져도 코드는 남을 수 있다. 실제 빌드 산출물을
  띄워 `` ` `` 를 눌러도 패널이 열리지 않고 `window.__GAME__` 이 없음을 확인한다.
- Three.js 를 별도 청크로 분리 (583 kB 한 덩어리 → 87 kB + 496 kB).
- `climbableFurniture()` 가 매 렌더 프레임 배열을 새로 만들던 것을 상수화.

### 도마뱀이 뒷걸음질치던 문제

플레이 중 보고된 버그다. **모델은 머리를 로컬 −Z 에 두고 만들었는데**
(`head.position.z = -0.36`, 꼬리 `+0.36`), `facing = atan2(dirX, dirZ)` 는 로컬
**+Z** 를 진행 방향에 맞추는 값이다. 그래서 꼬리가 앞장서서 180° 반대로 걸었다.

입력 매핑은 정상이었다 — 쿼터뷰라 `W` 가 화면 위쪽이 아니라 **위-오른쪽**으로
가는 것뿐이다(카메라가 남동 45도). 이건 아이소메트릭의 정상 동작이다.

고치면서 같은 회전 규약을 쓰는 `threatSide()` 의 역회전 부호도 뒤집혀 있던 것이
드러났다. 정면을 보고 있을 때 **오른쪽 위협을 왼쪽이라고 답해서** 겁먹은
눈동자가 반대로 돌아가고 있었다. 위 "겁먹으면 위협 쪽을 본다"는 이제야 사실이다.

`tests/gecko-facing.test.ts` 가 8방향 전부에 대해 **머리의 월드 좌표가 진행 방향
쪽에 있는지** 검사한다. 화면을 보지 않고 잡을 수 있어야 다시 어긋나지 않는다
(Three.js 의 Object3D 계산은 WebGL 없이 node 에서 돈다).

## 밸런스를 바꾸려면

모든 밸런스 상수는 **`src/core/GameConfig.ts` 한 곳**에 있다.

```bash
# 1. GameConfig.ts 수정
# 2. 해석·수치 모델로 재검증 (불합격이면 exit 1)
npm run balance
# 3. 실제 시스템으로 봇 플레이 실측
node tools/cycle-probe.ts
# 4. 회귀 테스트
npm test
```

`tests/balance.test.ts` 가 **평형 점유율 > 0.44** 와 **44% 도달 300~480초**를 강제한다.
이 테스트가 깨지면 상수를 되돌리거나, 의도한 변경이라면 `ROADMAP.md` §3 의 표를 갱신한다.

가구를 옮기면 `BLOCKED` 비율이 바뀐다. 허용 범위(10~15%)를 벗어나면
`tests/collision.test.ts` 가 실패한다. 실측값은 게임 시작 시 콘솔에도 출력된다.

자세한 검증 근거는 [`ROADMAP.md`](./ROADMAP.md) §3 참조.

## 알려진 문제

- **인간 적(§24)의 밸런스가 미해결이다.** 봇 측정에서 인간을 넣으면 신중한 플레이가
  5판 전부 아사한다 (인간 없이는 4/5 클리어). 사냥/휴식 주기(8초/25초), 추격 시간
  상한(5초), 시야 축소(6.0→3.5), 배고픔 회복 상향(10→13)을 모두 적용했으나 봇
  기준으로는 여전하다. 사인은 추격 자체가 아니라 **섭취 공백** 이다 — 배고픔 상한이
  100 이라 몰아 먹은 잉여가 버려지고, 피하는 동안의 긴 공백에서 0 이 된다.
  다만 이 봇은 쫓길 때마다 피난처로 가서 기다리는 과잉 대응을 한다. 인간이
  플레이어보다 느리므로(2.9 vs 3.2) 사람은 거리를 두며 계속 먹을 수 있어
  더 잘할 여지가 크다. **사람 플레이로 판단이 필요하다.**
  빼려면 `CONFIG.HUMAN_FROM_LEVEL` 을 99 로 두면 등장하지 않는다.
- 프로덕션 번들의 대부분이 Three.js 다 (496 kB / gzip 125 kB). 게임은 첫 화면부터
  Three.js 가 필요해 지연 로드할 여지가 없으므로 **전체 바이트는 줄지 않는다.**
  별도 청크로 분리해 둔 것은 캐시 분리 목적이다 — 게임 코드만 고치면 87 kB 만
  다시 받는다.
- 헤드리스 브라우저(E2E)에서는 렌더가 느려 **시뮬레이션이 실시간보다 느리게 돈다.**
  게임 자체의 문제는 아니지만, E2E 에서 무언가를 기다릴 때 벽시계를 기준으로
  삼으면 안 된다. `e2e/helpers.ts` 의 `advanceGameTime` / `expectWithinGameTime` 을
  쓰면 예산을 게임 시간으로 줄 수 있다. (아래 "S9 에서 고친 것" 참조)
